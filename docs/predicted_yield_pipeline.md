# Predicted-Table Yield Pipeline

This experiment connects the monthly feature forecasting outputs to the existing direct yield regression path.

## Command

```powershell
python scripts\research\yield_from_predicted_monthly_tables.py --include-baselines
```

By default, outputs are written under:

```text
outputs/predicted_yield_experiments/
```

The output directory is ignored by git, so generated CSVs, models, plots, and benchmarks do not modify the tracked baseline artifacts.

## Detailed Explanation

### What Source Tables Are Used

The script starts from the official extracted monthly feature table:

```text
outputs/experiments/corn_ia_monthly_2017_2022/artifacts/official_monthly_feature_table.parquet
```

This table is the clean monthly CropNet feature table. Each row is one county, crop, year, and month. The feature columns contain numerical AG, NDVI, and weather features.

For each requested forecasting source, the script builds a new generated monthly table:

```text
outputs/predicted_yield_experiments/predicted_monthly_tables/
```

The generated tables use this logic:

```text
January rows:
  copied from the official monthly table

February-December rows:
  generated by the selected forecasting source
```

With the default command, `known_months=1`, so January is treated as known and the rest of the year is predicted.

The generated table sources are:

| Table source | Meaning |
| --- | --- |
| `gru` | February-December features generated by the saved GRU checkpoint |
| `transformer_encoder` | February-December features generated by the saved Transformer encoder checkpoint |
| `lstm` | February-December features generated by the saved LSTM checkpoint |
| `naive_lag1` | February-December features copied recursively from the last available month |
| `seasonal_last_year` | February-December features copied from the same month in the previous year when available |
| `ensemble_mean` | Equal average of the learned generated tables |
| `ensemble_weighted` | Intended weighted average of learned generated tables; currently falls back to equal weights locally |

Each generated table is then used as the monthly feature source for a separate yield-regression experiment.

### What Labels Are Used

The predicted-table experiment does not invent new yield labels. It uses the same annual yield labels already present in the existing labelled training frame:

```text
outputs/yield_baseline/corn_ia_2017_2022_monthly_full/merged_monthly_training_frame.csv
```

That file was created by joining official monthly features with USDA annual county yield labels. The new script extracts the unique county-year yield labels from it, then joins those labels onto each generated monthly table.

The target is:

```text
yield_bu_acre
```

Because the yield label is annual, the same county-year yield value is copied onto every monthly row for that county-year. This matches the existing non-predicted monthly yield path.

### How The Yield Training Is Kept Comparable

For a fair comparison, the new predicted-table path reuses the same yield-regression functions as the official non-predicted path.

For each generated monthly table, the script runs:

```text
generated monthly table
  -> build_monthly_training_frame(...)
  -> prune_feature_columns(...)
  -> split_dataset(...)
  -> evaluate_models(...)
  -> evaluate_naive_baselines(...)
  -> save benchmarks, residuals, model, metadata
```

This is the same training/evaluation logic used by the direct official monthly feature baseline. The main variable being tested is therefore:

```text
Which monthly feature table did the yield model train on?
```

The default yield model candidates are:

```text
Ridge
RandomForest
ExtraTrees
BaselineTrainMean
BaselinePreviousYearSameCounty
```

XGBoost and LightGBM are not used by default. They only run when optional dependencies are available and `--include-optional-yield-models` is passed.

### What Holdout Set Is Used

The split is year-based:

```text
Train: 2017-2021
Test:  2022
```

The latest local run produced:

```text
train_rows = 5460
test_rows  = 1164
test_year  = 2022
```

So the reported RMSE, MAE, and R2 values are all measured on the 2022 holdout set.

The 2022 test rows are monthly rows, not one row per county-year. Since the target yield is annual, the same county-year yield label appears across the monthly rows for that county-year. For average actual and predicted yield, the row-level and county-year averaged values were effectively the same in the latest run.

### Where The Results Are Saved

The high-level comparison table is:

```text
outputs/predicted_yield_experiments/predicted_table_yield_summary.csv
```

Each table source also gets its own yield model folder:

```text
outputs/predicted_yield_experiments/yield_models/<table_source>/
```

Important files inside each folder:

| File | Meaning |
| --- | --- |
| `best_yield_model.joblib` | Saved final yield regressor for that table source |
| `yield_model_benchmark.csv` | RMSE, MAE, R2, and MAPE for candidate yield models |
| `prediction_residuals.csv` | 2022 holdout actual yield, predicted yield, residual, absolute error |
| `merged_predicted_monthly_training_frame.csv` | Generated monthly features joined with annual yield labels |
| `yield_model_metadata.json` | Source paths, split details, feature columns, best model, pruning report |
| `feature_group_benchmark.csv` | Yield results by AG/NDVI/weather feature group |
| `year_cv_benchmark.csv` | Leave-one-year-out style benchmark |
| `month_benchmark.csv` | Performance by month |
| `window_benchmark.csv` | Performance by month window |
| `yield_feature_importance.csv` | Feature importance for the saved final model |

For example, the best current predicted-table model is saved at:

```text
outputs/predicted_yield_experiments/yield_models/naive_lag1/best_yield_model.joblib
```

The non-predicted official yield model is separate and remains at:

```text
outputs/yield_baseline/corn_ia_2017_2022_monthly_full/best_yield_model.joblib
```

## What It Compares

The original non-predicted yield path trains on:

```text
official monthly AG/NDVI/weather features
  -> USDA annual yield labels
  -> monthly yield training frame
  -> Ridge / RandomForest / ExtraTrees / baselines
```

The predicted-table path trains on:

```text
official monthly AG/NDVI/weather features
  -> blank-fill monthly feature predictions
  -> generated monthly feature table
  -> same USDA annual yield labels
  -> same monthly yield training frame logic
  -> same Ridge / RandomForest / ExtraTrees / baselines
```

The yield comparison is intentionally kept close to the non-predicted path. The script reuses the same core yield functions from `src/cropnet_forecasting/yield_regression.py`, including:

- `build_monthly_training_frame`
- `prune_feature_columns`
- `split_dataset`
- `evaluate_models`
- `evaluate_naive_baselines`
- `evaluate_feature_group_benchmarks`
- `evaluate_year_cv`
- month/window benchmarks
- residual output
- feature importance output

This means the main experimental variable is the monthly feature table source.

## Limitations

- The predicted-table experiment uses the existing labelled yield frame as its label source instead of re-reading the original USDA CSV paths. This keeps the laptop run self-contained, but it assumes the existing labelled frame was built correctly.
- The current weighted ensemble falls back to equal weights across GRU, Transformer encoder, and LSTM. The local blank-fill summary does not contain comparable validation RMSE rows for all three learned models, so true validation-weighted averaging is not available yet.
- The learned forecasting checkpoints were trained in an earlier forecasting experiment, not jointly optimized for final yield prediction.
- `known_months=1` is only one inference setting. Results may change for `known_months=3`, `6`, `9`, or full-year observed tables.
- The simple `naive_lag1` source currently performs best, but that should be interpreted carefully. It may help the yield regressor by smoothing/repeating features rather than proving that naive monthly forecasting is agronomically stronger.
- XGBoost and LightGBM are not included by default. They only run if optional dependencies are installed and `--include-optional-yield-models` is passed.
- Generated outputs live under `outputs/`, which is gitignored. Reproduce the tables and benchmarks by rerunning the command above.
